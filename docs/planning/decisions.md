# Decision Log

Architecture and scope decisions for the Portable Web App Suite.
Background and reasoning: [`feasibility-study.md`](feasibility-study.md).

| ID | Date | Status | Decision |
|---|---|---|---|
| D-001 | 2026-10-15 | Accepted | **Optional relay for TCP protocols.** Apps run fully in the browser. Mail (IMAP/SMTP), SSH, SFTP/FTP and remote Postgres connect through an optional WebSocket-to-TCP relay, which also has an HTTP proxy mode for CORS-restricted HTTP services. **Everything that does not need the relay must work without it.** Apps enable network features only when a relay is configured. |
| D-002 | 2026-10-20 | Accepted | **Suite licence: EUPL-1.2** (`LICENSE`, `LICENSE-de.txt`), copyright Adrian Fuchs. Chosen for free use and redistribution, copyleft that also covers network use, an official German text, liability rules written for EU law and the GPL/LGPL/MPL compatibility clause (pykeepass and the German dictionary are GPL). `NOTICE.md` states the licensor's intention for Art. 5: the notice of modification must be obvious to users (title and about dialog, supported by the file `MODIFIED`), no use of the licensor's name for modified versions, and a non-binding objection to security-weakening modifications (a licence cannot forbid them; GPL-3.0 §7-style extra terms do not exist in the EUPL). Every app embeds the EUPL, the notice and its third-party components with their licence texts (about dialog). Previously open; ONLYOFFICE (AGPL) stays out of the `file://` variant for technical reasons (D-019). |
| D-003 | 2026-10-15 | Accepted | **Two delivery variants from one build.** (1) Single self-contained HTML file per app, opened via `file://`: the primary target. (2) Hosted PWA on a static HTTPS server: offline after first load, installable (better on Android), and with COOP/COEP headers for multithreaded WASM (video, LibreOffice/office engines). Features that need threads may be available in the PWA variant only. |
| D-004 | 2026-10-15 | Accepted | **Browser wrapper is reduced in scope** to a "Web Inspector": Eruda bookmarklet + HAR/page source/header analyzer. Inspecting arbitrary sites inside an iframe is technically impossible (same-origin policy, framing protection). |
| D-005 | 2026-10-15 | Superseded by D-009 | ~~Tech stack: TypeScript, Vite, pnpm, React.~~ Not possible without node/npm. |
| D-006 | 2026-10-15 | Accepted | **No secrets in browser storage.** Data that must persist goes into user files (JSON/XML or KDBX). localStorage/IndexedDB is used only for UI preferences and file handles, because Chromium shares storage between all `file://` pages. |
| D-007 | 2026-10-15 | Accepted | **Download fallback also on Android Chrome**, not only Firefox. The File System Access API is only available on Chromium desktop. |
| D-008 | 2026-10-15 | Accepted | **Documentation source is Markdown.** Confluence storage XHTML is generated by a Python script (as `tools/build_docs.py` in web-authenticator), in both German and English. |
| D-009 | 2026-10-15 | Accepted | **No node/npm, neither for the UI nor for the build.** Same approach as web-authenticator: plain JavaScript (no transpiling, no JSX, no TypeScript compiler), Preact + htm and Pico CSS for the UI, libraries vendored in `vendor/` (downloaded with `curl`, committed, documented in `vendor/README.md`), and a reproducible, stdlib-only Python `build.py` that inlines everything into one HTML file per app. Extensions: inlining of WASM/binaries (gzip + base64) and worker code, the PWA output, and ES-module-only libraries via an inline import map with `data:` URLs (spike S-1; fallback: prefer libraries with UMD builds). React-based libraries are handled per app (`preact/compat` or a vendored React 18 UMD build). WASM engines without a browser build are compiled once outside the normal build and committed as artifacts with reproducible build instructions. |
| D-010 | 2026-10-15 | Accepted | **The relay runs locally on the thin client and has several implementations**, so users can run whatever their system allows: **Python** (standard library only, reference implementation), **PowerShell** (.NET only, Windows), and a **shell** wrapper around existing tools (`websocat`/`socat`/`websockify`). Others (e.g. a static Go binary) only if needed. All implement one documented protocol (TCP tunnel with JSON header + HTTP proxy mode) and pass a shared pytest conformance suite. The relay binds to `127.0.0.1` with a random token, and **may terminate TLS** (plaintext only on loopback), so no TLS stack is needed in the browser. SSH stays end-to-end encrypted in the browser. |
| D-011 | 2026-10-15 | Accepted | **web-authenticator stays a separate project** (`../web-authenticator`, read-only from this repo). Its concepts are carried over: build and vendoring approach, `files.js` (File System Access API with download fallback), KDBX handling (kdbxweb + hash-wasm, KeePassXC-compatible fields, auto-lock), strict CSP meta tag, pytest + Playwright tests in Chromium and Firefox (incl. "no external references / no network requests"), reproducible releases with SHA-256 checksums, and the documentation pipeline. |
| D-012 | 2026-10-15 | Accepted | **Modern browsers only.** Current stable Chromium-based browsers and Firefox (desktop and Android). No polyfills or legacy browser support. Newer APIs (WebCodecs, `DecompressionStream`, import maps, File System Access API on Chromium desktop) may be used, with feature detection where support differs between browsers. |
| D-013 | 2026-10-15 | Accepted | **Settings formats: JSON and KeePass (KDBX).** XML is not a hard requirement and is not implemented for now. It can be added later as an import/export format if needed. |
| D-014 | 2026-10-15 | Accepted | **Assume minimal user rights on the client.** No admin rights, no installation, no package managers (pip, winget, apt), no system services, no firewall changes; possibly restricted PowerShell (execution policy, Constrained Language Mode) and no extra tools such as `websocat`/`socat`. Consequences: the relay is a single script started by the user, using only the standard runtime (Python stdlib, or PowerShell/.NET without modules); it listens on `127.0.0.1` on an unprivileged port (no URL ACL / `http.sys` reservation: the PowerShell variant implements WebSockets on a plain `TcpListener` instead of `HttpListener`, which also makes it work with PowerShell 7 on Linux); it writes nothing outside the user's own directories. If a policy blocks every runtime (e.g. PowerShell in Constrained Language Mode and no Python), network features are unavailable and the apps keep working offline (D-001). The shell variant is lowest priority, because the tools it needs are unlikely to be present. |
| D-015 | 2026-10-15 | Accepted (spikes S-1, S-2) | **ES-module libraries without a bundler.** `tools/vendor_esm.py` vendors npm packages from jsDelivr's `+esm` endpoint (one version per package, imports rewritten to bare specifiers, licenses recorded). `build.py` embeds the modules as text and creates Blob URLs and an import map at startup (much faster than `data:` URLs: Univer ready in 3–5 s instead of 16 s). Own code may also be split into modules imported by bare specifiers. Workers do not see the import map. |
| D-016 | 2026-10-15 | Accepted (spike S-1) | **CodeMirror 6** is the editor component for the text editor and other code/SQL editors. |
| D-017 | 2026-10-15 | Accepted (spike S-3) | **Relay protocol version 1** with TCP tunnel, STARTTLS control message and HTTP proxy, implemented in **Python** and **PowerShell** (both pass the same conformance tests). The relay terminates TLS; no browser-side TLS library. No shell variant for now (D-014). |
| D-018 | 2026-10-15 | Accepted (spike S-4) | **SSH/SFTP engine in Go compiled to WebAssembly** (x/crypto/ssh, pkg/sftp; BSD), shared by the SSH and SFTP apps, transported through the relay (end-to-end encrypted). Built by `tools/build_engine_ssh.py` with a portable Go toolchain; the result is committed in `vendor/wasm/`. ChaCha20-Poly1305 is preferred (fastest cipher in WASM). |
| D-019 | 2026-10-15 | Proposed (spikes S-2, S-6) | **Spreadsheet app on Univer Sheets** (Apache-2.0) for the `file://` variant, with own import/export: XLSX/XLSM via ExcelJS (values, formulas, shared formulas, styles, layout; `shared/js/univer-xlsx.js`), ODS/XLS/CSV via SheetJS CE (without styles). **ONLYOFFICE** (AGPL) is not feasible as a single HTML file; it is only an option for the hosted PWA variant, depending on the license decision (D-002). |
| D-020 | 2026-10-15 | Proposed (spikes S-6, S-8) | **Document app on Univer Docs** (Apache-2.0) with paginated layout and `@univerjs/preset-docs-drawing` for images. DOCX import with the own direct reader (`shared/js/docx-import.js`, S-8), DOCX export with the `docx` library (`shared/js/univer-docx.js`). The mammoth/HTML route is only kept for comparison. ODT later. |
| D-021 | 2026-10-15 | Proposed (spike S-7) | **Presentation app: own editor**, not Univer Slides (single-style text boxes only). Own deck model rendered as DOM/SVG (`shared/js/slide-render.js`), Moveable for move/resize/rotate, own PPTX reader with layout/master inheritance (`shared/js/pptx-import.js`, fflate), PPTX export with PptxGenJS (`shared/js/pptx-export.js`). |
| D-022 | 2026-10-15 | Accepted (spike S-6) | **Office font aliases:** `shared/css/office-fonts.css` maps Microsoft fonts to installed metric-compatible fonts with `@font-face`/`local()`; no font downloads. |
| D-023 | 2026-10-15 | Accepted (spike S-8) | **Stub modules for excluded lazily loaded modules.** `tools/vendor_esm.py` writes small replacement modules for modules excluded from vendoring (e.g. Univer's hyphenation dictionaries of other languages), so that their dynamic `import()` does not fail. |
| D-024 | 2026-10-15 | Accepted | **Python notebook added to the scope** (AGENTS.md, "Data science"): Jupyter-like notebook and console with pandas, numpy, matplotlib and more, completely on the client, `.ipynb` files. |
| D-025 | 2026-10-15 | Accepted | **Notebook on Pyodide** in a worker, with an own kernel producing Jupyter outputs. Bundled packages (≈ 43 MiB, 49 MB HTML): numpy, pandas, matplotlib, seaborn, sympy, networkx, lxml, beautifulsoup4, pyyaml, xlrd, openpyxl, regex, requests, sqlite3, SQLAlchemy, pykeepass, nzpy, micropip. Packages load on first import (also indirect imports); numpy/pandas/matplotlib are preloaded in the background. Heavier packages (scipy, scikit-learn, statsmodels, polars, duckdb, pyarrow) can be added as optional add-on packs later. User-supplied wheels (pure Python or built for Pyodide's Emscripten platform) can be installed from files. |
| D-026 | 2026-10-15 | Accepted | **Large vendored distributions are committed** like all vendored files (Pyodide ≈ 43 MiB in `vendor/pyodide/`), so the build works offline without a download. `tools/vendor_pyodide.py` updates them and `vendor/pyodide.lock.json` records their SHA-256. |
| D-027 | 2026-10-15 | Accepted (spike S-9) | **Workers run classic scripts only.** On `file://`, workers cannot load ES modules (no module workers from Blob URLs in Chromium; no `import()`/`importScripts()` of Blob URLs in workers). ES-module code needed in a worker is converted to classic scripts at vendoring time and concatenated into one worker script. |
| D-028 | 2026-10-15 | Accepted | **All apps work on mobile devices in a meaningful way** (touch, small screens, on-screen keyboard): responsive layouts without horizontal page scrolling, reachable functions (e.g. scrollable toolbars), larger touch targets; every app has a test in a phone-sized viewport with touch emulation. Functions that need a mouse/keyboard (e.g. rectangular selection) may be desktop-only. |
| D-029 | 2026-10-15 | Accepted | **App documentation per app** in `docs/en/apps/<app>.md` and `docs/de/apps/<app>.md` (same file names), linked from the user guides; the technical documentation has one section per app. |
| D-030 | 2026-10-16 | Accepted | **Undo and redo in every editor**, with toolbar buttons (touch devices) and `Ctrl/Cmd+Z`, `Ctrl/Cmd+Y`, `Ctrl/Cmd+Shift+Z`. Libraries with an own history keep it (CodeMirror, Univer); apps with an own model use snapshots (`shared/js/history.js`, `Suite.UndoHistory`); the database tool uses database snapshots for SQLite and inverse statements for Postgres grid edits. Opening/closing files is not a step; saving keeps the history. |
| D-031 | 2026-10-16 | Accepted | **Overview app (`overview.html`) with all apps embedded** (≈ 70 MB). Apps start in tabs (iframes) or windows by writing their HTML into `about:blank` documents, which keep the overview's origin and secure context on `file://` (Blob URL documents are opaque and insecure in Chromium). The overview's CSP is the union of all app policies (inherited by the written documents). Single apps can be saved as files, all apps into a folder or a ZIP. |
| D-032 | 2026-10-16 | Accepted | **Apps interact through “Open with…”** (`shared/js/bridge.js`): a source app hands a file to a target app over `postMessage` and saves it back through a `MessagePort` (file-handle stand-in used by `Suite.files.save`). Inside the overview, targets open as tabs; standalone apps open the sibling file `<app>.html` in a new window (apps must stay in one folder with their original names). |
| D-033 | 2026-10-16 | Accepted | **Relay protocol version 2: remote relays with authentication.** The relay may run on another machine or behind a reverse proxy (nginx, Apache, HAProxy): `--bind`, own TLS certificate, `--trusted-proxy` (only its `X-Forwarded-*` headers count), `--base-path`, allowed host names. Sign-in by token (as before), by **user accounts** (PBKDF2-SHA256 hashes in a JSON file shared by all implementations, per-account target allow-lists, sessions with sliding expiry, rate-limited logins) or by the reverse proxy (user header, e.g. client certificates). Credentials are only accepted over TLS or from the local machine unless explicitly allowed. Extends D-010/D-017; version 1 clients keep working. The relay apps' CSP allows `connect-src http: https: ws: wss:`. |
| D-034 | 2026-10-16 | Accepted | **Second presentation app on reveal.js ("Web slides", `apps/reveal`)** besides the PPTX editor (D-021): a visual editor for the reveal.js features (2-D slide structure, blocks with fragments and auto-animate, Markdown/HTML slides, backgrounds, transitions, speaker notes, themes and deck options). Output is a self-contained reveal.js HTML file that also embeds the editor model; Markdown and Jupyter notebooks (slideshow metadata) can be imported. reveal.js 6 (MIT) is vendored as classic builds with fonts de-duplicated (`tools/vendor_reveal.py`). |
| D-035 | 2026-10-18 | Accepted | **Audio editor: clips, beat grids, compressed export.** Tracks hold movable clips (Audacity model: ripple editing of ranges, clips dragged by a title bar in time and between tracks). Beat detection produces a constant-tempo grid per clip (spectral-flux onset envelope, autocorrelation tempo, grid fine search) and cues; clips snap edge/beat/cue to edge/beat/cue. Tempo changes keep the pitch (WSOLA). Export to MP3 and FLAC with Mediabunny's LAME/libFLAC WebAssembly encoders (MPL-2.0; LAME itself is LGPL, see D-002), Ogg Opus and M4A AAC where the browser has WebCodecs encoders. Browsers have no built-in MP3 encoder, which was the reason for WAV-only export before. |
| D-036 | 2026-10-18 | Accepted | **Phone layout as a shared pattern.** Below 760 px the header toolbar becomes a scrolling row of its own; side panels are drawers (`suite-drawer`) that start below the header (`--suite-top`, measured by the shell) above a shade (`Suite.shell.backdrop`) that closes them, so the button that opened a drawer can always close it. Every browser test also runs on a phone display (`pytest --mobile`), where the fixtures open and close drawers like a user. |
| D-037 | 2026-10-18 | Accepted | **Keyboard shortcuts are documented once.** The "Keyboard shortcuts" section of each app's user documentation (EN/DE) is the source; `build.py` embeds it and the shell's ? dialog (F1) shows it. |
| D-038 | 2026-10-18 | Accepted | **Encrypted ZIP with own crypto code.** WinZip AES needs a little-endian AES counter that WebCrypto cannot do, and the archive model is synchronous, so SHA-1/HMAC/PBKDF2/AES are implemented in `apps/archive/src/js/zipcrypto.js` (checked against FIPS-197/RFC 6070 vectors and pyzipper) instead of adding zip.js. |
| D-039 | 2026-10-18 | Accepted | **PDF page operations with pdf-lib** (MIT, loaded on demand); encrypted PDFs stay read-only for page operations. |
| D-040 | 2026-10-18 | Accepted | **Barcode application on ZXing-C++ (zxing-wasm).** One WebAssembly library (1.5 MB) reads and writes all common 1D and 2D codes in every browser; the native BarcodeDetector is missing on desktop Chromium and in Firefox. Symbols are drawn by the app (colours, quiet zone, SVG/PNG). |
| D-041 | 2026-10-18 | Accepted | **Recovery copies in IndexedDB** (`shared/js/autosave.js`) for all editors while they are dirty, offered on the next start; not for KeePass (no decrypted database in browser storage) and never passwords. Copies are a crash safeguard, not a backup. |
| D-042 | 2026-10-19 | Accepted | **KaTeX for formulas in web slides**, vendored with WOFF2 fonts inlined (`vendor/katex`) and embedded only in presentations that contain `$$…$$`, `\\(…\\)` or `\\[…\\]` (about 0.6 MB). reveal.js' math plugin is not used (it loads KaTeX from a CDN); MathJax would be larger. A single `$` is not a delimiter (prices, shell code). |
| D-043 | 2026-10-20 | Accepted | **Spell checking with Hunspell (WebAssembly) in all prose fields.** hunspell-asm (MIT; Hunspell used under LGPL-2.1) replaces nspell, which has no compound support and flags ordinary German words (*Fahrradweg*). English (dictionary-en, MIT/BSD) and German (igerman98 as packaged in dictionary-de, GPL-2.0/3.0, unmodified) are embedded in the eleven apps with prose text; further Hunspell dictionaries are loaded by the user (.aff/.dic or .oxt). One suite-wide setting (header selector, off by default); marks with the CSS Custom Highlight API (mirror elements for textareas), CodeMirror decorations (prose fully, code only comments and strings), the document editor keeps its panel (canvas). The browser's own checking is switched off in fields the suite checks. |
